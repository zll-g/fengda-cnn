# 2 号启动锅炉核心异常监测预警模型神经网络结构方案

版本：V1.6  
编制日期：2026-09-14  
适用场景：NOx 排放异常、过热蒸汽温度偏高、过热蒸汽压力偏高

## 1. 设计结论

采用一个“工况条件化多变量 LSTM-AE”共享模型即可覆盖三个核心异常场景，不需要为 NOx、蒸汽温度、蒸汽压力分别训练三个独立神经网络。工况编码作为模型输入进入编码器和解码器；它不是只在阈值选择时使用的外部标签。

模型仅使用正常运行数据进行无监督训练，学习不同正常工况下 25 个运行测点之间的时序耦合关系。在线时，模型重构当前 60 秒窗口；真实值与重构正常值之间的偏差形成测点异常贡献。三个场景在共享重构结果上使用不同的场景评分模块、工况阈值和运行建议规则。

该设计保留现有未来 60 秒预测模型的职责：预测模型用于趋势前瞻和 FGR 调节建议；本模型用于当前异常识别、异常分级和根因定位。两个模型建议并行部署，不相互替代。

## 3. 数据输入与窗口定义

### 3.1 输入测点

模型输入为方案要求的燃烧系统、汽水系统、烟气排放系统全量运行测点，目标接口规模为 `25` 个连续或离散测点。具体测点清单应以 Auto Historian 当前导出字段和 `point_registry` 映射为准。

关键类别包括：

- 燃烧与配风：中心气阀位、外环气阀位、风门阀位、鼓风机频率、电流、天然气流量。
- FGR：FGR 调节阀位、FGR 风机频率。
- 汽水系统：蒸汽压力、蒸汽温度、蒸汽流量及可用的减温水、给水相关测点。
- 炉膛与烟气：炉膛出口烟温、炉膛出口烟压、烟囱温度、压力、烟气流量、湿度。
- 排放：烟囱 NOx、SO2、O2、粉尘、NO2。

对于暂未接入或质量无效的测点，不允许静默以常数替代。当前固定 25 维模型不支持任意缺失特征的降级推理：任一过程输入测点无效时必须禁止评分，并在数据接入层记录原因，避免产生误导性预警。

训练前必须形成并评审 `point_registry`，该文件是模型、在线服务和前端共用的数据契约。没有完成 25 个测点的一一映射和验收，不允许启动正式训练。

| registry 字段 | 必填内容 |
|---|---|
| `point_id` / 中文名称 | 唯一稳定标识及 DCS/运行人员使用的中文名称 |
| `historian_tag` | Auto Historian 原始字段名及数据来源 |
| 单位与量程 | 原始单位、工程量程、有效范围、是否需单位换算 |
| 类型与聚合 | 连续/离散、1 秒聚合规则（末值、均值、最大值或计数） |
| 质量规则 | 空值、坏质量、量程外、跳变、允许插值时长及处理结果 |
| 场景属性 | 是否为 NOx/温度/压力目标点、关联权重、是否关键测点 |
| 版本与责任人 | 生效版本、确认日期、运行/热控责任人 |

关键测点包括三个场景目标点及其场景关联关键量。任一属于 25 个过程输入的测点缺失、质量无效或单位不匹配时，在线服务必须全局禁止 LSTM-AE 推理并产生数据质量事件；不得使用旧值或常数补齐。仅当 25 个过程输入完整、但某一场景的独立限值或阈值配置无效时，才禁止该场景评分并允许其余场景部分评分。中心气阀位和外环气阀位仅用于运行/停机判定：其无效值遵循 3.4 的“按未打开处理”，使服务进入 `stopped`、`not_scored`，同时记录阀位数据质量事件。

### 3.2 张量形状

| 项目 | 设计值 | 说明 |
|---|---:|---|
| 时间粒度 | 1 秒 | 与现有 Historian 数据和预测模型一致 |
| 输入窗口长度 | 60 秒 | 识别当前异常及其短期发展过程 |
| 基础输入维度 | 25 | 全量过程测点 |
| 输入张量 | `[batch, 60, 25]` | 一个样本为过去连续 60 秒 |
| 内部掩码维度 | 3 | NOx、过热蒸汽温度、过热蒸汽压力的掩码指示通道 |
| 模型输入张量 | `[batch, 60, 28]` | 25 个过程量与 3 个内部掩码通道拼接；掩码由服务生成，不由 Historian 提供 |
| 更新频率 | 1 秒 | 每秒生成一个最新窗口 |
| 重构输出 | `[batch, 60, 25]` | 重构同一段历史窗口 |

### 3.3 预处理

1. 按 1 秒重采样并按测点业务规则聚合。
2. 保留原始质量标志，剔除通信中断、量程外、明显错误和长时间缺失样本。
3. 离线训练仅对连续点、长度不超过 2 秒且两端质量均为 `good` 的内部孤立缺口做线性插值；目标测点、阀位和工况 GMM 特征不允许插值。在线评分不对任何模型输入做插值或旧值填充，60 秒窗口内任一模型输入无效即不评分。
4. 所有连续测点使用训练集正常数据计算的 Z-score 参数标准化。
5. 离散测点使用 0/1 编码；不对离散测点进行不合理插值。
6. 标准化参数、有效测点清单、窗口配置必须与 ONNX 模型一同版本化保存。

“部分评分”仅适用于模型输入完整、但某一场景的独立限值或阈值配置暂不可用的情况。任一 25 个过程输入测点缺失、无效或单位不匹配时，全局状态必须为 `data_unavailable`，不得以部分过程量执行 LSTM-AE 推理。

### 3.4 停机判定与窗口准入

停机状态只依据燃烧器两个燃气阀位的实际反馈值判定，不叠加风机、流量、压力等辅助条件。该规则同时用于离线训练样本筛选和在线评分开关：

| 条件 | 判定 |
|---|---|
| 燃烧器中心气调节阀阀位反馈有效且 `> 1%` | 运行 |
| 燃烧器外环气调节阀阀位反馈有效且 `> 1%` | 运行 |
| 两个阀位均 `<= 1%` | 停机 |
| 任一阀位为空、非数值、`NaN` 或无穷值 | 该阀位按未打开处理 |

逻辑表达式为：`is_running = is_open(center_gas_valve) OR is_open(outer_ring_gas_valve)`，其中 `is_open(v)` 仅在 `v` 可解析为有限数值且 `v > 1.0` 时为真；否则为假。`is_stopped = NOT is_running`。

除运行状态外，服务还必须输出独立的 `valve_data_status`：`valid`、`center_invalid`、`outer_invalid`、`both_invalid`。阀位无效时仍遵循“按未打开处理”的停机规则，但状态原因必须记录为“数据不可用导致未评分”，不得与“阀位实际关闭”混淆。该数据质量事件需要进入运行审计和可用率统计。

- 训练、验证与测试只接收窗口内每一个秒点均为“运行”的样本；60 秒窗口内只要存在任一秒为停机，该窗口即剔除。
- 在线状态为停机时，不执行 LSTM-AE 推理、异常评分和预警输出；界面应明确显示“停机，未评分”。
- 由停机转为运行后的稳定时间、以及由运行转为停机前的过渡时间，作为单独配置项管理；初版建议均排除 60 秒，以避免启停瞬态污染正常样本。该过渡规则不改变上述停机本身的判定条件。

## 4. 工况识别模块

### 4.1 目的

点火后、升负荷、稳态燃烧和降负荷时，变量组合与波动范围差异明显。停机及其过渡时段不进入模型；对其余运行工况若共用一个阈值，仍极易将正常切换误判为异常。

### 4.2 推荐实现

仅针对满足运行阀位规则、且通过数据质量校验的窗口，采用无监督聚类识别工况，初始推荐 `3~5` 个工况簇：

- 点火后稳定阶段。
- 升负荷与过渡过程。
- 稳态低负荷。
- 稳态中高负荷。
- 降负荷过程（数据量充足时单独保留）。

聚类不使用 LSTM-AE 潜变量，避免“先得到模型潜变量才能识别模型输入工况”的循环依赖。聚类输入只采用定义运行模式的非目标特征：燃气流量、中心气/外环气阀位、风门阀位、鼓风机频率、FGR 阀位、FGR 风机频率、可用风量和蒸汽流量的均值、标准差及末端 10 秒斜率。NOx、O2、过热蒸汽温度、过热蒸汽压力以及三个场景的其他目标报警量不得进入 GMM，避免异常本身影响工况编码并削弱重构残差。

初版采用 GMM（Gaussian Mixture Model）输出工况概率：在训练集正常运行窗口上，以 BIC 最小值从 `K=3,4,5` 中选择簇数；每个工况簇必须至少覆盖 `5%` 的训练窗口且不少于 `2,000` 个窗口，否则合并到最接近簇。GMM 特征、标准化参数、簇中心和编号映射均随模型版本冻结。

在线维护“已确认工况”和“候选工况”两个状态。最大后验工况与已确认工况不同时，只有候选工况后验概率不低于 `0.70` 且连续保持 `10` 秒，才提交为新的已确认工况；提交时只触发一次 30 秒 `condition_settling`。候选工况在 10 秒内改变或置信度下降时，放弃候选并保持原已确认工况，不重置稳定期。最大后验概率连续 `10` 秒低于 `0.70` 时才进入 `condition_unconfirmed`；模型异常分数只输出提醒级，不允许升级为预警或报警；已批准的工程限值触发不受此限制。

### 4.3 运行原则

- 已确认工况发生变化后进入固定 `30` 秒的 `condition_settling` 状态；期间保留原始得分和审计记录，但最多输出提醒级，不对异常得分做人工衰减。未确认的候选工况变化不进入稳定期，也不重置稳定期计时。
- 工况置信度不足时输出“工况未确认”，不直接发出高等级报警。
- 训练、验证、上线均使用同一套工况编码与阈值版本。

## 5. 共享 LSTM-AE 网络结构

### 5.1 结构参数

采用单向 LSTM，以保证在线计算时只使用当前时刻及其过去数据；不使用未来信息。AE 为序列到序列重构结构，潜变量由整个 60 秒输入窗口压缩得到。工况 GMM 的簇编号经 Embedding 后，分别拼接到编码器和解码器输入，使模型学习不同工况下的正常耦合关系。

| 模块 | 层/操作 | 输入形状 | 输出形状 | 神经元/通道 | 激活与正则化 |
|---|---|---|---|---:|---|
| 过程输入层 | 60 秒多变量窗口 | `[B, 60, 25]` | `[B, 60, 25]` | 25 | 标准化后输入 |
| 目标掩码层 | 3 个场景目标的掩码指示 | `[B, 60, 3]` | `[B, 60, 3]` | 3 | 由训练/评分服务生成，`1` 表示该目标值已隐藏 |
| 模型输入层 | Concat(过程输入, 目标掩码) | `[B, 60, 25]` + `[B, 60, 3]` | `[B, 60, 28]` | 28 | 掩码不会改变重构目标 |
| 输入投影 | TimeDistributed Linear | `[B, 60, 28]` | `[B, 60, 64]` | 64 | LayerNorm + GELU + Dropout 0.10 |
| 工况嵌入 | Condition Embedding + Repeat | `[B, 1]` | `[B, 60, 8]` | 8 | GMM 工况编号；置信度不足不评分 |
| 编码器 LSTM-1 | 单向 LSTM | `[B, 60, 72]` | `[B, 60, 96]` | 96 | 输入为投影与工况嵌入拼接；输出 Dropout 0.10 |
| 编码器 LSTM-2 | 单向 LSTM | `[B, 60, 96]` | `[B, 60, 64]` | 64 | 输出 Dropout 0.10 |
| 时序注意力池化 | Additive Attention | `[B, 60, 64]` | `[B, 64]` | 64 | 注意力权重和为 1 |
| 潜变量层 | Linear | `[B, 64]` | `[B, 32]` | 32 | LayerNorm + Tanh |
| 时间/工况条件扩展 | Repeat + Time Embedding + Condition Embedding | `[B, 32]` | `[B, 60, 48]` | 32 + 8 + 8 | 60 个位置嵌入和同一工况嵌入 |
| 解码器 LSTM-1 | 单向 LSTM | `[B, 60, 48]` | `[B, 60, 96]` | 96 | 输出 Dropout 0.10 |
| 解码器 LSTM-2 | 单向 LSTM | `[B, 60, 96]` | `[B, 60, 64]` | 64 | 输出 Dropout 0.10 |
| 输出投影 | TimeDistributed Linear | `[B, 60, 64]` | `[B, 60, 25]` | 25 | 线性输出 |

其中 `B` 为批量大小。核心可训练层为 9 组：输入投影、工况嵌入、2 层编码器 LSTM、注意力层、潜变量层、2 层解码器 LSTM、输出投影；若将目标掩码、拼接、LayerNorm、Dropout、时间嵌入等单独计层，则总计不少于 17 个功能层。

### 5.2 前向计算

设标准化过程输入窗口为 `X`、目标掩码为 `M`、将掩码位置目标值置为 0 后的输入为 `X_masked`，模型重构结果为 `X_hat`：

```text
H0 = Dropout(GELU(LayerNorm(Linear(Concat(X_masked, M)))))
c  = Repeat(ConditionEmbedding(condition_id), 60)
H1 = LSTMEncoder1(Concat(H0, c))
H2 = LSTMEncoder2(H1)
C  = AttentionPool(H2)
z  = Tanh(LayerNorm(Linear(C)))
D0 = Repeat(z, 60) concat TimeEmbedding(0...59) concat c
D1 = LSTMDecoder1(D0)
D2 = LSTMDecoder2(D1)
X_hat = Linear(D2)
```

该结构通过 32 维潜变量压缩 60 秒内 25 个测点的正常耦合关系。异常工况通常无法被正常模型准确重构，因此会产生明显的重构残差。掩码通道避免模型将当前待评分目标值直接带入重构路径，增强对目标异常的可检测性。

### 5.3 损失函数

训练仅使用已筛选的正常窗口，并采用掩码去噪训练：对三个场景目标随机选择连续 `1~10` 秒片段置为标准化 0，同时将相应 `M=1`，重构目标始终使用未掩码的原始 `X`。至少 `50%` 的训练样本保留无掩码输入，以维持全量重构能力。

在线评分时，对每个场景独立执行一次前向推理：将该场景目标测点的最后 10 秒置为 0，并将对应掩码通道置为 1；实际目标值仅用于与 `X_hat` 计算残差，不作为该 10 秒的模型输入。这样得到的重构值是基于历史上下文和其他过程量的“正常基准”。

推荐组合损失：

```text
L = L_recon + 0.20 * L_trend + 0.05 * L_last
```

其中：

- `L_recon`：逐测点 Huber 重构损失；掩码目标位置使用 `2.0` 倍权重，降低偶发噪声对训练的影响并强化条件重构能力。
- `L_trend`：真实值与重构值的一阶差分误差，保证模型学习正常变化速度，降低快速变化时的误报。
- `L_last`：窗口末端 10 秒的加权重构误差，使在线实时判定更关注当前状态。

可根据测点重要性配置损失权重。NOx、蒸汽温度、蒸汽压力及其关键关联量应有更高权重，但不能高到使其他测点失去异常定位价值。

## 6. 异常得分与三级预警

### 6.1 测点级残差

对测点 `j`、时刻 `t` 计算标准化残差：

```text
r(t,j) = abs(X(t,j) - X_hat(t,j))
```

窗口测点异常分数使用末端加权平均：

```text
S_j = 0.7 * mean(r(t,j), t=最后10秒) + 0.3 * mean(r(t,j), t=全部60秒)
```

偏离方向保留为：

```text
d_j = mean(X(t,j) - X_hat(t,j), t=最后10秒)
```

`d_j > 0` 表示实际值高于同工况正常重构基准，`d_j < 0` 表示低于正常基准。

三个首期场景均为“偏高风险”，因此绝对残差不能直接作为升级依据。对场景目标点定义高值方向门控：

```text
G_dir = 1, 当 d_target > direction_deadband
G_dir = 0, 其他情况
```

其中 `direction_deadband` 由各工况正常验证集的目标点有符号残差上侧噪声分布标定，初版取正向残差的同工况 `P75`。`S_trend` 单独衡量上升速率，不作为高值方向门控的必要条件；因此，目标值持续偏高但走势平稳时，仍可因 `S_target` 或 `S_limit` 触发预警。若 `G_dir = 0`，该场景模型分数为 0，不得由模型分数触发“偏高”提醒、预警或报警；工程限值触发按 6.2 的独立规则执行。未来如需监测低 NOx、低温或低压，应建立独立的低值场景与相反方向门控，不与本方案混用。

### 6.2 场景评分头

三个场景评分头不额外训练为分类网络，而是使用共享 LSTM-AE 的重构残差、变化率和业务安全边界计算。这符合“无异常标签训练”的要求，也方便运行人员解释。

| 场景 | 主关注测点 | 场景分数构成 | 预警方向 |
|---|---|---|---|
| NOx 超标 | NOx、O2、FGR 阀、FGR 风机、天然气、风门、鼓风机、中心气/外环气、炉膛烟温 | NOx 残差 + 关联量残差 + NOx 上升趋势 + 距排放限值距离 | NOx 实际值高于基准，或达到工程限值；快速上升会提高得分 |
| 蒸汽温度偏高 | 蒸汽温度、炉膛烟温、蒸汽压力、蒸汽流量、燃气、FGR | 温度残差 + 热负荷关联残差 + 升温速率异常 + 距温度保护限值距离 | 蒸汽温度高于基准，或达到工程限值；快速升温会提高得分 |
| 蒸汽压力偏高 | 蒸汽压力、蒸汽流量、燃气、风量、阀位、稳压/排放相关测点 | 压力残差 + 产汽/用汽失衡残差 + 压力上升速率 + 距保护限值距离 | 蒸汽压力高于基准，或达到工程限值；快速升压会提高得分 |

场景分数推荐形式：

```text
S_scene = w1 * S_target + w2 * S_related + w3 * S_trend + w4 * S_limit
```

- `S_target`：目标测点重构残差的同工况归一化分数。
- `S_related`：同场景关联测点重构残差加权和的同工况归一化分数。
- `S_trend`：目标测点实际斜率相对同工况正常斜率偏离的同工况归一化分数。
- `S_limit`：距排放限值、温度保护值、压力保护值的归一化距离。

为使各分量和权重可解释，先在正常验证集、同一工况、`G_dir=1` 的样本上分别建立经验累积分布函数 `F_c`，并计算：

```text
S_target  = F_target,c(raw_target_residual)
S_related = F_related,c(raw_related_residual)
S_trend   = F_trend,c(max(0, raw_slope_deviation))
```

上述三个分量均截断在 `[0, 1]`；`S_limit` 已在 `[0, 1]`。初版不允许在线移除任一分量后重新分配权重，因为这会使离线标定的场景阈值失效。任一必需分量、关联权重、限值配置或场景阈值配置不可用时，对应场景进入 `data_unavailable`，不得输出数值分数；其余完整配置的场景可按 `partially_scored` 规则继续评分。

对“偏高”场景，`S_limit` 的固定计算式为：

```text
S_limit = clip((y_target - L_remind) / (L_alarm - L_remind), 0, 1)
```

`L_remind` 为运行专业确认的提醒参考值，`L_alarm` 为辅助报警参考值，二者均使用与实时测点一致的工程单位，且必须满足 `L_alarm > L_remind`。NOx 必须在 `point_registry` 中明确是原始浓度还是折算浓度，并使用对应的合规参考值；温度、压力必须引用已批准的工艺/保护参考值。限值、关联权重和阈值配置需作为完整场景评分配置独立版本化并记录审批人。目标测点无效时按过程输入无效处理并全局不评分；限值或场景评分配置无效时，对应场景不评分，不得以 0、历史值或运行时重分配权重代替。

工程限值是对模型分数的独立兜底，不得被 `G_dir`、工况未确认或工况切换状态抑制：目标测点质量有效时，`y_target >= L_remind` 连续 3 秒至少输出提醒级，`y_target >= L_alarm` 连续 3 秒至少输出辅助报警级。该规则只影响辅助预警输出，不能替代 DCS、联锁或保护动作。

初始权重建议为 `w1=0.45`、`w2=0.25`、`w3=0.20`、`w4=0.10`。最终得分为 `G_dir * S_scene`。实际权重需通过正常历史回放、异常事件回放和运行专业人员评审后固化。`overall_score` 定义为所有可评分场景分数的最大值；没有可评分场景时为 `null`，不能为 0。

### 6.3 阈值与持续性

每个工况、每个场景独立从正常验证集且 `G_dir=1` 的样本得分分布生成阈值。阈值统计以非重叠 60 秒块为基本样本，禁止将 1 秒滑窗视为独立样本：

- 提醒级：至少 `2,000` 个有效块时，取同工况 `P95` 附近，且连续 `3` 个窗口触发。
- 预警级：至少 `5,000` 个有效块时，取同工况 `P99` 附近，且连续 `5` 个窗口触发。
- 报警级：至少 `10,000` 个有效块时，取同工况 `P99.5` 附近，或安全边界距离进入危险区间，且连续 `3` 个窗口触发。

当有效块数量不满足某一级的要求时，该级不得启用；例如只有提醒级样本量时，最大输出提醒级。`S_trend` 已进入场景得分，“持续上升”不作为独立跳级条件，避免状态机出现歧义。

上述分位数和持续秒数为初始建议，必须结合误报率、漏报风险、现有保护阈值和运行规程进行现场标定。报警级仅作为辅助提示，不能替代现有 DCS/保护逻辑。

### 6.4 预警状态机与解除规则

每个场景独立维护状态：`normal`、`reminder`、`warning`、`alarm`、`data_unavailable`、`stopped`、`condition_unconfirmed`、`condition_settling`。状态转换必须带时间戳、得分、工况、模型版本和原因码，供追溯审计。

| 当前状态 | 进入条件 | 解除或降级条件 |
|---|---|---|
| normal -> reminder | 满足提醒阈值连续 3 秒 | 得分低于提醒解除阈值连续 10 秒 |
| reminder -> warning | 满足预警阈值连续 5 秒 | 得分低于预警解除阈值连续 15 秒，降为 reminder |
| warning -> alarm | 满足报警阈值连续 3 秒 | 得分低于报警解除阈值连续 30 秒，降为 warning |
| 任意非停机、目标点质量有效状态 -> reminder | 目标值达到 `L_remind` 连续 3 秒 | 目标值低于 `L_remind - limit_hysteresis` 连续 10 秒，按模型得分重新判定 |
| 任意非停机、目标点质量有效状态 -> alarm | 目标值达到 `L_alarm` 连续 3 秒 | 目标值低于 `L_alarm - limit_hysteresis` 连续 30 秒，先降为 warning；仅在低于 `L_remind - limit_hysteresis` 连续 10 秒后，才允许按模型得分继续降级 |
| 任意状态 -> stopped | 按 3.4 判定停机 | 重新运行且经过配置的稳定排除时间后，回到 normal |
| 任意状态 -> data_unavailable | 任一 25 个过程输入无效，或全部场景配置无效 | 过程输入恢复连续 60 秒并完成窗口填充，且至少一个场景配置有效后，回到 normal |
| 任意评分状态 -> condition_unconfirmed | GMM 最大后验概率低于 0.70 连续 10 秒 | 置信度连续 30 秒恢复后，按当前得分从 normal 重新计时 |
| 任意评分状态 -> condition_settling | 新候选工况以不低于 0.70 后验连续确认 10 秒 | 保持 30 秒；工况置信度满足要求后按当前得分从 normal 重新计时 |

状态判定优先级固定为：`stopped`（包含阀位无效按未打开）> `data_unavailable` > 工程限值触发 > `condition_unconfirmed` / `condition_settling` > 模型分数状态。`limit_hysteresis` 由运行专业按场景和单位配置，必须大于 0。模型解除阈值初始取对应进入阈值的 `90%`，形成滞回，避免阈值附近频繁闪烁。`condition_unconfirmed` 期间模型分数不升级；连续 30 秒工况置信度恢复后再按当前得分重新计时。报警确认、静默和人工备注只影响通知策略，不得改变原始得分与审计记录。

## 7. 根因定位与原因输出

### 7.1 测点贡献度

使用场景内、有效测点范围的归一化残差贡献度：

```text
denom = sum(weight_k * S_k for k in available_scene_points)
Contribution_j = weight_j * S_j / denom, 当 denom > epsilon
```

当 `denom <= epsilon` 或不存在有效场景测点时，`top_contributors` 返回空数组并标记 `contributor_status: "unavailable"`；不得执行除零或返回虚假的 0% 贡献。每次预警输出贡献度前 5 的测点、实际偏离方向、实际值、重构基准值和变化率。对高度相关的同类测点可进一步聚合为“FGR 系统”“空燃比”“燃烧器配气”“减温水/给水”“蒸汽调压/泄压”等原因组。

### 7.2 场景原因映射

- NOx：FGR 出力不足、空燃比失衡、中心气/外环气配比异常、燃烧高温区异常。
- 蒸汽温度：减温水不足、给水出力不足、减温阀迟缓、炉膛热负荷异常。
- 蒸汽压力：压力调节阀迟缓、产汽与用汽失衡、稳压/排放阀响应不及时。

原因映射规则必须同时满足“关键测点贡献度高”和“偏离方向符合物理逻辑”；仅有单点重构误差时，应输出“需核查”而非确认具体故障。

## 8. 训练方案

### 8.1 正常样本定义

- 仅纳入经运行人员确认、无报警、无超标、无保护动作、无明显传感器故障的历史窗口。
- 仅覆盖满足运行阀位规则的点火后、升负荷、稳态和降负荷正常工况；停机状态不参与训练。
- 明确排除停机窗口、启停过渡窗口、已发生 NOx 超标、超温、超压、设备检修、仪表漂移、通信中断和人工强制操作异常时段。

### 8.2 数据集划分

- 按时间和运行批次划分训练、验证、测试集，禁止同一连续运行过程的相邻窗口跨集合泄漏。
- 正常验证集用于确定 early stopping、工况模型、方向死区、同工况阈值和持续性规则；不得使用测试集反复调参。
- 测试集应包含未参与训练的完整运行批次，用于回放验证正常误报率和已知异常的提前量。

### 8.3 异常事件验证与标注

LSTM-AE 的参数训练只使用正常窗口，但预警能力必须在独立异常事件集上验证。上线前建立 `event_registry`，每个事件至少包含：事件 ID、运行批次、场景、起止时间、传统报警时间、人工确认时间、真实原因、处置结果、数据可用性、审核人和审核日期。

- NOx、蒸汽温度、蒸汽压力三个场景分别至少准备 `10` 个已复核异常事件；数量不足时，只能以影子模式运行，不能宣称检测性能达标。
- 每个事件按“事件前正常段、异常发展段、处置恢复段”回放，统计首次提醒、首次预警、首次报警、提前量、漏报和误报。
- 事件标签仅用于阈值、权重、原因码和验收评估，不反向混入 LSTM-AE 的正常重构训练集。
- 根因无法确认的事件标记为 `unknown_cause`，可以用于检验报警，但不得用于验证原因码准确率。

### 8.4 初始训练超参数

| 参数 | 初始值 |
|---|---:|
| 窗口长度 | 60 秒 |
| 滑窗步长 | 1 秒 |
| batch size | 256 |
| optimizer | AdamW |
| learning rate | 0.0005 |
| weight decay | 0.0001 |
| 最大 epoch | 80 |
| early stopping patience | 10 |
| dropout | 0.10 |
| 梯度裁剪 | 1.0 |
| 潜变量维度 | 32 |

训练产物必须以不可变版本目录保存：训练数据批次清单及哈希、`point_registry` 版本、停机/过渡规则版本、GMM 参数、标准化参数、目标掩码协议版本、网络权重、ONNX 文件、限值与阈值配置、训练命令、随机种子、指标报告和审批记录。任何一点变化均生成新模型版本，不覆盖已上线版本。

## 9. 在线部署接口

### 9.1 输入

```json
{
  "window_end": "2026-09-14T10:30:00+08:00",
  "timestamps": ["2026-09-14T10:29:01+08:00", "...", "2026-09-14T10:30:00+08:00"],
  "feature_contract_hash": "sha256:...",
  "points": [
    {
      "point_id": "stack_nox_mg_m3",
      "unit": "mg/m3",
      "values": [101.2, "... 共60个数值 ...", 103.4],
      "quality_flags": ["good", "... 共60个质量标志 ...", "good"]
    }
  ],
  "point_registry_version": "registry_v1",
  "limit_config_version": "limits_v1"
}
```

`timestamps` 必须为严格递增的 60 个、间隔 1 秒的带时区时间戳；`points` 必须恰为 `point_registry` 中模型版本指定的 25 个 `point_id`，顺序可任意但服务须按冻结的特征顺序重排。`values` 与 `quality_flags` 必须各有 60 项。外部接口只传 25 个原始过程量；服务在完成质量校验和标准化后，按当前场景生成 3 个内部掩码通道，构造 ONNX 所需的 `[1, 60, 28]` 输入张量。

`feature_contract_hash` 固定采用 `SHA-256`：按模型特征索引升序，对每个点生成一行 `index|point_id|canonical_unit|aggregation|valid_min|valid_max|type|normalization_type|normalization_params_sha256\n`，末尾追加 `mask_protocol_version|target_point_ids|mask_value\n`；数值使用小数点和不带千分位的规范十进制文本，拼接结果使用无 BOM 的 UTF-8 编码后计算哈希。`normalization_type` 初版固定为 `z_score`，`normalization_params_sha256` 为训练集冻结的每点均值、标准差及零方差处理规则文件的摘要。`mask_protocol_version` 固定当前三目标、最后 10 秒掩码及标准化 0 值的规则。该哈希在模型构建时生成并写入模型产物；服务端只接受与模型产物完全一致的值，禁止由客户端运行时自行定义契约。

服务在接收窗口后必须校验时间连续性、窗口长度、点位集合、单位、质量标志、配置版本和 `feature_contract_hash`。任一关键项不通过时，不调用模型评分，并返回明确的数据质量原因码。

当停机时，返回 `run_state: "stopped"` 与 `score_status: "not_scored"`；当任一 25 个过程输入无效、或全部场景配置不可用时，返回 `score_status: "data_unavailable"`、不可用点位或配置原因码。仅部分场景配置不可用时返回 `partially_scored`。系统不得将“未评分”序列化为数值为 0 的正常分数。

全局 `score_status` 取值固定为：三个场景均完成评分时为 `scored`；至少一个场景完成评分、但并非全部完成时为 `partially_scored`；没有任何场景可评分时为 `data_unavailable`；停机时为 `not_scored`。`overall_score` 仅在 `scored` 或 `partially_scored` 时取全部可评分场景的最大值，其余状态为 `null`。每个场景必须单独返回 `status`、不可评分原因码及可用性信息。

`score` 用于分级，`score_multiple` 表示当前场景分数相对于 `active_threshold.value` 的倍数；`active_threshold` 必须返回当前生效的阈值级别、数值和工况编号。工程限值触发时，`active_threshold.level` 使用 `engineering_remind` 或 `engineering_alarm`，数值为对应工程限值。上述得分均可能在极端异常时饱和。为保留严重程度，每个场景还必须输出未截断的 `raw_residual`、`raw_slope_deviation` 和目标实际值/重构值，前端不得仅以 `score=1` 判断异常严重程度。

## 10. 模型漂移与再训练治理

在线服务按工况、场景和测点持续记录残差分布、工况占比、缺失率、阀位数据可用率、预警率和推理时延。以当前已批准模型的正常验证集为基线，每日和每运行批次计算以下漂移指标：

- 目标点与总体残差的 PSI；`PSI > 0.20` 连续 3 天进入“需复核”，`PSI > 0.30` 连续 3 天暂停自动升级并发出模型维护工单。
- 关键点缺失率；任一关键点日缺失率超过 `1%` 时，优先排查数据链路，不以模型重训替代。
- 工况占比；任一工况占比相对训练基线变化超过 `30%` 时，复核是否出现新运行模式。
- 影子模式误报率或已知事件漏报率超过已批准验收目标时，启动模型复核。

再训练必须通过“数据筛选、离线指标、异常事件回放、影子模式、运行/热控/环保审批”五个阶段。新模型不得自动替换生产模型；保留当前生产版本和一键回退配置。

## 11. 与现有预测模型的协同关系

| 能力 | 现有 CNN-LSTM-Attention 预测模型 | 新 LSTM-AE 预警模型 |
|---|---|---|
| 训练数据 | 正常和可用历史时序监督样本 | 仅正常运行样本 |
| 输出 | 未来 60 秒 NOx/O2/NO2 预测曲线 | 当前异常得分、三级预警、贡献度、原因码 |
| 关注重点 | 趋势前瞻和 FGR 调节建议 | 偏离正常工况、异常定位和风险分级 |
| 适合回答的问题 | “未来一分钟排放可能如何变化？” | “当前参数组合是否异常，异常由什么导致？” |

当 NOx 场景预警触发时，可将预测模型未来 60 秒的 NOx/O2 走势作为补充证据，提高调整建议的可信度；但两者的报警逻辑保持独立，避免预测模型误差直接触发异常报警。

## 12. 影子模式与验收指标

- 影子模式至少覆盖 `30` 个有效运行日和每个主要工况不少于 `10` 次完整运行批次；期间只记录和通知，不自动干预操作。
- 正常历史回放及影子模式：报警级误报不超过每场景每 `24` 小时 `1` 次，预警级误报不超过每场景每 `8` 小时 `2` 次。最终阈值由运行专业确认。
- 已复核异常事件：三个场景分别统计提醒/预警/报警召回率与提前量；初版目标为预警级召回率不低于 `80%`，相对传统报警的中位提前量不低于 `30` 秒。事件数量不足时仅报告结果，不判定达标。
- 根因定位：有明确原因记录的事件中，贡献度前 3 测点或原因组与运行记录一致率不低于 `70%`。
- 工况切换稳定性：点火后、升负荷、降负荷阶段分别统计误报率；`condition_unconfirmed` 与 `data_unavailable` 不计为正常，也不允许掩盖报警统计。
- 在线性能与可用性：1 秒更新频率下，端到端 P95 耗时小于 `300 ms`；关键数据可用时评分服务日可用率不低于 `99.5%`。

## 13. 实施边界

- 本系统为辅助监测预警与运行建议工具，不替代 DCS、联锁、保护、环保合规判定或运行规程。
- 所有报警阈值、保护边界和调整建议均需由运行、热控、环保专业人员联合确认。
- 初版上线应先以“影子模式”运行：记录预警但不干预操作，完成回放和现场对照后再开放正式提示。
